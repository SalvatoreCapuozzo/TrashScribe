* Do not commit or push unless the owner asks; staging on request is fine.
* Order GPU work by the expected significance of the result: the run that can change the paper's claims most goes first.
* Report progressively: hand-written journal in `RESULTS.md`, every code or protocol change with hypothesis and decision in `attempts/ATTEMPTS.md`.
* Proactive improvements are welcome inside an approved direction ("if you see it could improve, yes"), but never state a claim before the evidence exists.
* The owner wants significant claims explained plainly, with numbers; when the data do not support what they hope to claim, say so and propose the experiment that could support an honest version.

**Why:** stated by the owner between 5 and 25 Nov 2026 ([HISTORY.md](../HISTORY.md)).

**How to apply:** check these before any commit, queue change or claim. Related: [[paper-style-rules]], [[honest-sam3-claim]].
